2. 项目背景与目标

2.1 背景

用户为独立语文教师，面向小学、初中学生，每月进行排课（每天哪些时段给哪个学生上课）。当前用纸质表格记录，存在以下痛点：

  • 学生请假 / 教师请假后，顺延课程容易忘记补，导致「欠课漏补」；
  • 每月实际上课情况无法实时汇总，难以一眼看清「哪些上了、哪些顺延了、什么原因」；
  • 纸质记录难以统计收入（实际上课节数 × 课程价格）。

2.2 目标

  • 提供一个 Web 系统，集中管理学生 / 时间段 / 课程 / 排课；
  • 实时查看每个月的上课情况，并管理每节课的上课状态；
  • 自动汇总待补课，闭环「顺延 → 安排补课 → 已补」；
  • 按月统计上课情况与收入。

2.3 成功标准

  • 排课可在当月网格中拖拽完成；
  • 前台首页能展示待补课列表（无则不展示）；
  • 当月课程表可标记状态并记录顺延原因；
  • 月收入 =（正常上课 + 已补）节数 × 学生价格，可按月查询。

5. 功能详述

5.1 学生管理

字段 姓名、年级（小/初 + 年级）、电话、家长微信、家庭地址、课程价格、状态（在读 / 暂停）、专属颜色、备注。

  • 列表 + 搜索（按姓名 / 年级）；
  • 详情可查看该生所有课程与待补课数；
  • 删除保护：有未结课程 / 未来排课时禁止硬删，仅可置「暂停」归档。

5.2 时间段管理

字段 开始时间、结束时间、排序。

  • 增删改 + 拖拽排序；
  • 校验不能重叠（如 08:00–10:00 与 09:00–11:00 冲突须拦截）；
  • 作为排课网格的「列」。

5.3 课程管理

因只上语文，课程 = 某个学生的一门语文课。字段：归属学生、科目（固定语文）、单价（取自学生课程价格）、备注。

  • 列表按学生分组；可停用（学生不学则保留历史）；
  • 价格修改仅影响之后排课，不回溯历史。

5.4 排课系统

交互：左侧学生列表（可拖拽）；中间当月网格——首列为日期（当月每一天一行），首行为时间段（每列一时段）；中间单元格为可拖拽区域。

  • 把学生拖入某单元格 → 生成一条当天该时段的课；每格仅能拖入 1 名学生（1 对 1）；
  • 排课只能排当月；历史月后台不可排；
  • 保存时，后端先查询上月所有「顺延」课，有则随保存一并关闭（视为已安排进本月）；
  • 保存后支持按学生生成当月课表图片（PNG，用于留存 / 发家长）；
  • 网格无课显示空白，周末不置灰。

5.5 请假与顺延

在当月课程表（前台）或排课条目上，可标记某节课状态为顺延，弹窗必填：

  • 请假方：学生请假 / 老师请假；
  • 顺延原因（自由文本，计入字典「顺延原因」可选预设）。

标记顺延后，该课进入待补课池。

5.6 补课闭环与待补课

  • 待补课定义：任意月份中状态 = 顺延且未关闭的课；
  • 前台首页实时查询所有待补课：有则列表展示，无则不展示；
  • 每条待补课可操作「已安排进本月课程」→ 关闭该待补（状态置已补 / 已安排）；实际补课由教师在排课网格把该生拖到某天某时段完成；
  • 跨月消除：上月没上的课，本月（或后续月）排入课程表后，经关闭动作即不再是待补；
  • 补课日期可落任意月（存字段），不额外占用网格单元。

5.7 字典管理

维护字典表，本期包含：年级、顺延原因预设。供下拉与选项复用；后续可扩展备注标签等。

5.8 数据总览

  • 按月查询（含历史月）；
  • 当月 / 历史月展示：排课总数、已上、顺延（学生请假 / 老师请假各几次）、已补、作废、待补；
  • 历史月额外展示未上课课程表 + 原因；
  • 月收入 =（正常上课 + 已补）节数 × 该生课程价格；顺延未补 / 作废不计入；
  • 顺延原因分类统计：学生请假 vs 老师请假次数。

5.9 今日视图（落地页）

  • 进入系统默认页；展示今天的课程清单；
  • 每节课一键标记：未上 → 正常上课 / 顺延（填原因）；
  • 顺带提示「今日待补课程」。

5.10 当月课程表（状态管理）

复用排课同款月网格，每格点开可管理状态：正常上课 / 顺延（填原因）/ 已补 / 作废；顺延标红并显示原因。

7. 课程状态机

状态含义可达下一状态
未上已排课、尚未发生正常上课 / 顺延 / 作废
正常上课已按时完成（终态）
顺延学生 / 老师请假，需补课已补 / 作废（经「已安排进本月课程」关闭）
已补补课已完成（终态）
作废不补（如长期停课）（终态）

未来日期显示「未上」；过去日期由教师在今日视图 / 当月课程表标记。顺延 → 安排补课 → 已补 构成补课闭环。

8. 非功能需求

  • 平台：Web 优先（桌面拖拽排课）；移动端功能稳定后实现，届时排课改用「点格选学生」；
  • 登录：本期无登录；
  • 存储：后端数据库（MySQL），数据持久化；
  • 性能：单月课表 < 1000 单元格，交互即时；
  • 可备份：数据库定期备份（由部署侧保障）。

10. 范围与排期

10.1 MVP（本期）

  • 学生 / 时间段 / 课程 / 字典 管理；
  • 排课系统（当月网格拖拽、每格 1 人、保存关上月顺延、按学生出图）；
  • 请假顺延（填原因）、补课闭环、待补课首页；
  • 今日视图、数据总览（按月、历史月未上课表 + 原因、月收入、顺延分类）、当月课程表状态管理。

10.2 后续（本期不做）

  • 移动端适配；
  • 登录 / 多角色（分享学生家长）；
  • 假期 / 停课日设置；
  • 数据备份导出 / 导入、报表打印导出（按学生出图保留）；
  • 收费 / 课时包余额。

11. 风险与待确认

  • MySQL 连接信息（库名 / 账号 / 密码）由用户后续补充；
  • 「已安排进本月课程」关闭待补时，是否需自动在网格生成补课单元 —— 本期采用「仅关闭 + 教师手动拖入补课」；
  • 顺延跨多个月（早于上月）的待补，依赖首页手动关闭或对应月份保存时关闭；
  • 月收入口径以「正常上课 + 已补」计，顺延未补 / 作废不计，待用户最终确认。
