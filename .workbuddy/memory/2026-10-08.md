## application.yml 配置重组（第二轮，修致命写法）

拆分后的三个文件有 2 处会让 Spring Boot 3.2 起不来的写法，已修：

1. 公共 `application.yml` 里原本写了 `spring.config.activate.on-profile: dev`
   → 整份公共配置被绑到 dev；prod 下 mybatis-plus 的 mapper-locations /
   type-aliases-package / 驼峰映射 / id-type 全部丢失（Mapper XML 找不到）。
2. `application-dev.yml` / `application-prod.yml` 里原本各写了 `spring.profiles.active`
   → Boot 2.4+ 明令禁止在 profile 专属文件里声明 active，
   会抛 `InvalidConfigDataPropertyException`，**启动直接崩**。
   `spring.profiles.active` 只能出现在公共 `application.yml`。

## Bug 修复：时间段录入 Jackson 反序列化失败（11:31）
- 现象：`POST /api/time-slots/create` 报 `JSON parse error: Cannot deserialize value of type java.lang.Integer from Boolean value (token VALUE_TRUE)`。
- 根因：后端 `TimeSlot.enabled` 是 `Integer`（注释"启用 1/0"），`create(@RequestBody TimeSlot)` 直接绑实体；前端 `timeSlot.ts` `createTimeSlot` 发 `enabled: data.enabled ?? true`（boolean，el-switch），Jackson 拒 Boolean→Integer。
- 系统性问题：后端 `enabled` 全用 `Integer`，而前端 `types/index.ts` 里 `TimeSlot`/`Course`/`Dict` 的 `enabled` 均为 `boolean`（第 34/46/97 行）——只有前端实际发出该字段的接口才会炸。
- 修法（仅 TimeSlot，用户只报这个）：后端 `TimeSlot.enabled` → `Boolean`；`TimeSlotServiceImpl.createTimeSlot` 默认 `setEnabled(true)`；`checkOverlap` `.eq(getEnabled, true)`。`applyPartial` 透传无需改。前端零改动（本就 boolean）。
- **只修 TimeSlot，未动 Course/Dict（同款 Integer/boolean 不一致，按用户"只改当次要求"原则只汇报）**：若 Course/Dict 的 create/update 也发 `enabled`，会同样报 400，需同样把各自实体 `enabled` 改 `Boolean` 或前端发 1/0。
- 验证：本机无 JDK，未 mvn compile；MyBatis BooleanTypeHandler 对 int/tinyint 列 0↔false 映射，无需改表。
