## application.yml 配置重组（第二轮，修致命写法）

拆分后的三个文件有 2 处会让 Spring Boot 3.2 起不来的写法，已修：

1. 公共 `application.yml` 里原本写了 `spring.config.activate.on-profile: dev`
   → 整份公共配置被绑到 dev；prod 下 mybatis-plus 的 mapper-locations /
   type-aliases-package / 驼峰映射 / id-type 全部丢失（Mapper XML 找不到）。
2. `application-dev.yml` / `application-prod.yml` 里原本各写了 `spring.profiles.active`
   → Boot 2.4+ 明令禁止在 profile 专属文件里声明 active，
   会抛 `InvalidConfigDataPropertyException`，**启动直接崩**。
   `spring.profiles.active` 只能出现在公共 `application.yml`。

重组后的分层（唯一正确结构）：

| 文件 | 放什么 |
|---|---|
| `application.yml` | server.port / application.name / profiles.active / datasource.driver / mybatis-plus 基础 / logging.root |
| `application-dev.yml` | datasource(url+账号密码，默认 localhost root/123456) / SQL 日志 StdOutImpl / com.lesson.schedule=debug |
| `application-prod.yml` | datasource(url 默认 47.116.35.76，账号密码**不给默认值**→未注入即启动失败) / NoLoggingImpl / warn |

- dev/prod 的 datasource 改为同构：均 `${DB_HOST}:${DB_PORT}/${DB_NAME}` + DB_USER/DB_PASSWORD。
- prod 凭据故意不设默认值（fail-fast），避免误用开发默认值连上生产库。
- 其余保留：useSSL=false、characterEncoding=utf8mb4（**后者不是 Java 字符集名，
  规范写法是 UTF-8**，当前能连但不保证所有驱动版本都宽容——待用户决定是否改）。
- 校验：pyyaml 6.0.3 解析三份均通过；脚本模拟 deep-merge，确认 dev/prod 都能取到
  mybatis-plus 全量配置（venv：`C:/Users/wanzh/.workbuddy/binaries/python/envs/default`）。
- 未编译验证（本机无 JDK / 未 mvn compile）。
