## 竞品调研：讯飞/智学网/组卷网的组卷与录题（2026-10-10）
- 制卷骨架（行业通用，值得照搬）：左题目列表 + 右试卷（试题篮）→ 组卷中心才排版。题目卡挂「组卷使用次数」；已入卷的题在列表置灰；试题篮有题型/难度分布统计；导出选 A4 竖 / B4 横双栏。
- 录题四条路：① 手动逐题录 ② 拍照识题（App）③ 上传 Word/PDF 划题标注（PC 主力）④ Excel/Word 模板批量导入。
- **两个关键判断**：
  1. 组卷网「拍照组卷」不是 OCR 生成题，而是**拿图片去千万级题库匹配**，所以准。我们没有可比对的题库，这条路不可复制。
  2. 智学网「每道小题必须点保存编辑，否则丢失」是**设计缺陷**，不能学。批量场景要统一提交。
- 该抄的三段式：**解析预览 → 修错 → 确认导入**。

## 卷内编辑改版：快照 → edited 标记位 + override 独立表（2026-10-10 当日重构）
用户反馈：**「不要用快照，加个字段标识是否被编辑过」**，追问后确认真正不爽点是**「字段多、表变宽」**（不是机制本身）。
- 定案 **B 方案**：`paper_question` 瘦身回 5 列（`id/paper_id/question_id/sort_order/edited`），删掉上一轮的 6 列 `snap_*`；
  编辑过的题面内容挪进新表 **`paper_question_override`**（`id/paper_question_id(唯一)/qtype/stem/options/answer/analysis/difficulty`）。
  语义与快照方案**完全等价**：`edited=0` 读 question 表；`edited=1` 读 override 表（查不到回落题库=双保险）。
- 迁移：schema.sql 里对旧库用 `information_schema` 判断后 `ALTER TABLE ... DROP COLUMN snap_*`（有才删），并补 `edited`（无才加），已验证可重复执行。
- 后端：新实体 `PaperQuestionOverride` + Mapper；`PaperServiceImpl` 组装出口仍是 `toQuestionVOsFromLinks()`，
  一次性批量查 override 避免 N+1；`setQuestions` 整体覆盖时**先删旧编排项对应的 override 再删编排项**；
  `clone`/`reuse` 抽了 `copyOverride(fromId,toId)` 复制内容。
- 前端：`api/paper.ts` 的 `PaperQuestionItem` 字段名**不变**（窄字段仍平铺，后端 DTO `Item` 也未变），
  所以制卷台 `PaperComposeView.vue` **零改动**——这是选这个方案的一个隐性好处（api 契约稳定）。
- **关键印证**：备课页「智能推荐题目」`PrepServiceImpl.suggest` 是**直接从 question 表按 kpId 捞通用题**、绕过试卷编排的。
  所以「编辑直接改题库」会让备课推荐被静默污染——这正是否决 A 方案（只加标记+直接改题库）的硬证据。
- 验证：`mvn -o compile` 通过；迁移幂等实测（跑两次，列数恒 5、snap_left=0）；
  起 18888 实测 **编辑→写 override / 读回读 override / 题库原题未变 / reuse 带 override / 还原(edited=false)→override 行被删** 全对；
  `vue-tsc --noEmit` + `vite build` 通过；产物已核；测完清库 + taskkill 40300 关 18888。
- **踩坑**：本机 curl 走代理会报 `upstream connect failed`，探本机端口必须加 `--noproxy '*'`（或 `--noproxy ''`）。
  另外后台起服务不要用 `nohup ... &`（会被判为任务结束），直接 `run_in_background` 跑 mvn 本体。

## 示例数据脚本 seed.sql（2026-10-10 交付）
- 新增 `backend/db/seed.sql`：**幂等可重复执行**的全量示例数据（与 `schema.sql` 并列）。
- 覆盖：6 学生（跨 1~6 年级，含原有张三）→ 6 门语文课 → 10月整月排课 54 节（四态齐全：
  NORMAL 13 / ABSENT 2 / MADEUP 2 / UNTAKEN 37）→ 备课备注 + 排课备注 + 6 条 lesson_knowledge
  → 题库 51 题（覆盖字词/句子/阅读/古诗文/写作/基础）→ 3 份试卷（12 条 paper_question）。
- **幂等实现**：学生按 `name` 判重、课程按 `student_id` 判重、时间段时间判重、
  课节按 `(lesson_date, slot_id)` 判重、题目按 `stem` 判重、试卷按 `title` 判重。
  实测连跑 3 遍条数完全一致。
- **踩坑 1（重要）**：`lesson` 有 `uk_lesson_date_slot` 唯一约束，**同一天同一时段只能 1 人**。
  造整月排课必须先把 6 人分成 3 组错开星期、组内 2 人分占 slot1/slot2，否则撞约束整批中断。
- **踩坑 2**：脚本里**不要硬编码 `student_id=1..6`** —— 库非空时自增 id 不从 1 开始
  （实测重跑后 id 是 7~12）。一律用 `JOIN student s ON s.name=...` 按姓名定位。
- **踩坑 3**：`prep_remark` / `remark` 的 UPDATE 日期必须落在该生**实际有课的星期**，
  否则静默 0 行（我第一次把张三的课写成 10-10 周六，实际他是周一/周四组，改到 10-12 才对）。
- 当天 10-10 是周六，只有组 C（陈梦豪 slot1 / 刘一诺 slot2）2 节课，这是日期决定的，不是 bug。
